# Phase-End Handoff: Task #835, Phase 2

**Immediate Next Action**: Begin Phase 3 (literature-search.sh loud flagging + quarantine).

**Current State**: Phases 1 and 2 completed. `.claude/scripts/literature-fidelity-audit.sh` exists
with working `--dry-run` (default) and `--write` modes. The real `~/Projects/Literature/index.json`
has been stamped: 153 entries now carry `provenance_fidelity` + `word_ratio` (90 true root entries
+ 63 phantom-parent-fallback child entries across 15 directories). A timestamped backup
(`index.json.bak.20260709-190805`) exists and was verified byte-identical to the pre-write state.
A second `--write` run confirmed idempotency (0 changed / 153 unchanged, empty diff). Population:
52 no_source_pdf, 5 not_yet_converted, 35 verified_conversion (30 healthy + 5 disclosed partial),
4 unverified_no_baseline, 1 unverified_summary (rabinovich_2014 — the sole confirmed case).

**Key Decisions Made**:
- Target-entry resolution uses `.path` prefix matching (`sources/<dir>/`) rather than `.id`-name
  matching against the directory name — more robust, and required to correctly handle directories
  hosting multiple independent top-level docs (thomas_2003_reactive -> thomas_2003_ch01 +
  thomas_2003_ch03) and the baier_katoen_2008 12-part split.
- Proof-completeness threshold calibrated to `< 0.6` (not the initially-guessed 0.5) after
  measuring rabinovich_2014's actual proof_fraction (0.545) — see phase-1-progress.json
  `approaches_tried` for the two failed intermediate thresholds and why they misfired.
- Definition headings use a content-length adequacy bar (>=2 non-blank lines or >=15 words);
  Lemma/Theorem/Proposition/Corollary headings require an explicit "Proof" marker in the body —
  this asymmetry (claims need proof, definitions need content) is what correctly separates
  rabinovich_2014 (bare unproved clauses) from the 5 disclosed partials.

**Deviations from Plan**:
- Phase 2 task "only touch parent entries, never child chunk entries" was altered: 15 of the 97
  directories have a pre-existing, orthogonal index.json metadata gap (children reference a
  `parent_doc` value with no corresponding top-level `id` row — a phantom parent). These are
  stamped directly on their child entries as a documented fallback; otherwise doets_1987 and
  venema_1991 (two of the plan's own named disclosed-partial acceptance-criterion benchmarks)
  would be unstampable and would fail-open to a false `unverified_summary` flag in Phase 3/4's
  retrieval-side lookups. Full rationale and the 15-directory list are in the auditor script's
  header comment and in `progress/phase-2-progress.json` deviation 2.5.

**What NOT to Try**:
- Do not use `chunk_*.md` filename presence or a standalone `## Overview` heading as detector
  signals — both are rejected false discriminators per report 01 (0 of 30 healthy docs use the
  `chunk_*.md` convention).
- Do not lower the proof-completeness threshold back to 0.5 or use a raw "N non-blank lines"
  adequacy bar for claim headings — both were tried and both failed to flag rabinovich_2014 (see
  phase-1-progress.json `approaches_tried`).
- Do not attempt to "fix" the phantom-parent metadata gap (create synthetic top-level index
  entries for venema_1991 etc.) — out of scope; the path-prefix + fallback design already handles
  it correctly for this task's purposes.

**Critical Context**: For Phase 3/4, the retrieval-side lookup by `doc_id` (from SQLite chunk
rows) against `index.json` must replicate the SAME two-step resolution: first try
`select(.id == $doc_id)`, and if that yields nothing, fall back to
`select(.parent_doc == $doc_id) | .provenance_fidelity` from ANY matching child (since the
phantom-parent directories were stamped only on children). Otherwise Phase 3/4's fail-open lookup
will incorrectly treat venema_1991/doets_1987/etc. chunks as missing the field and flag them as
unverified — reproducing the exact false-positive Phase 2's fallback was built to avoid.
