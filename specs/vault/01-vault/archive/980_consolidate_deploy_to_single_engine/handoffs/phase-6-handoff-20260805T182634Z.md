1. `[Regenerate]` calls `manager.wipe` (via `exts.wipe`), not `manager.regenerate` directly —
   `manager.wipe` is the function that actually performs the full six-step destructive sequence
   (snapshot -> rm -rf -> regenerate -> restore -> re-apply -> clear staging); `manager.regenerate`
   alone does not remove `base_dir` first. `manager.wipe`'s own doc comment already names both
   `deploy-headless.sh --wipe` and the picker `[Regenerate]` entry as its two call sites.

   `is_regenerate` instead, matching how `is_help`/`is_reload_all` are already excluded from the
   same guards — a special entry should never be treated as an editable/loadable artifact.

   exclusive callees (see Current State above) rather than leaving provably-dead code behind.
4. `test-deploy-propagation.sh`'s `REPO_ROOT` fix uses `git rev-parse --show-toplevel` as the
   primary resolution (works from any depth) with the original fixed-depth computation kept only
