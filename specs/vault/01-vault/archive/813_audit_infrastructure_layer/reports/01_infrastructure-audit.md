## Context & Scope

This audit covers the infrastructure layer only: the 65 executable scripts in `.claude/scripts/`, the 19 extension manifests in `.claude/extensions/*/manifest.json`, the 14 hook scripts in `.claude/hooks/` plus their wiring in `.claude/settings.json`, and `.claude/extensions.json`. It explicitly excludes commands/skills/agents content (task 811) and rules/context/docs content (task 812), except where a finding straddles layers (noted inline). Per the batch context, the just-landed changes from tasks 804/808/809/810 (the `--fable` model branch, `task-lock.sh init-marker` + cross-task scope mutex, and the gate-script sourcing in `/research`/`/plan`/`/revise`) were audited for robustness like any other code, not flagged as regressions relative to a prior HEAD. All analysis was read-only against the live tree; the one behavioral check performed (`check-extension-docs.sh`) is itself read-only/reporting. No `.claude/` files were modified, no locks were touched, and no destructive git operations were run.

## Methodology

1. **Robustness sweep**: enumerated shebang line and `set` flags for all 65 scripts; classified deviations (no `set` line, `set -uo pipefail` without `-e`, non-`env` shebangs) and manually inspected each deviating script's header/comments to distinguish intentional design (e.g. sourced libraries that must use `return`, not `exit`; validators that accumulate pass/fail counts and must not abort mid-scan) from unexplained inconsistency.
2. **jq-escaping-workaround compliance**: grepped all scripts for jq filter strings containing the raw `!=` operator (the Issue #1132 anti-pattern documented in `jq-escaping-workarounds.md`) and separately verified, for extension `keyword_overrides` entries, that the actual consumer jq pattern in `commands/task.md` executes without error against each manifest (this surfaced IN-02 by direct reproduction, not inference).
3. **Dead/orphaned script detection**: built a reference count for every script filename across all `.sh`/`.md`/`.json` files in `.claude/` (excluding the file itself); scripts with zero or near-zero references were individually inspected to confirm true orphan status vs. legitimate low-traffic scripts (e.g. test-only callers).
4. **Extension manifest conformance**: validated all 19 manifests as JSON; diffed top-level key sets across all 19 to find schema drift; cross-checked `dependencies`, `routing`, `routing_hard`, and `keyword_overrides` against the documented schema in `context/guides/extension-development.md` and `docs/architecture/extension-system.md`; ran `check-extension-docs.sh` (the project's own doc-lint) to completion and inspected every FAIL/WARN line.
5. **Hooks and settings wiring**: enumerated every `command` string under `settings.json`'s `hooks` object and cross-referenced it against the physical contents of `.claude/hooks/`; found the delta by inspecting which hook scripts exist but are never referenced.
6. **Concurrency review**: read `task-lock.sh` in full given its central role in tasks 787/788/808/809 (this session itself holds live locks under `specs/*/.lock/`, so all timing/race analysis was static, not exercised against the live lock state).
7. **Performance spot-check**: profiled `generate-todo.sh`'s and related state-mutating scripts' jq-call patterns for O(N) or worse redundant re-parsing of `specs/state.json` given its "called after nearly every status transition" role.
8. **Dependency-loader verification**: located the actual circular-dependency/depth-limit implementation (outside `.claude/`, in `lua/neotex/plugins/ai/shared/extensions/init.lua`) since CLAUDE.md's claim about this behavior needed an implementation-level check, not just a docs read.

## Prioritized Recommendations

1. **(IN-01, CRITICAL)** Wire `validate-meta-write.sh` into `settings.json`'s `PostToolUse` array. *Preserved functionality*: the hook's own logic (advisory `additionalContext`, never blocking; `specs/*` paths always exempt; only `.claude/{commands,skills,agents,rules,context,extensions}/*` and `*/CLAUDE.md` trigger) is unchanged — only the missing registration is added, using the exact same invocation pattern (`bash .claude/hooks/X.sh 2>/dev/null || echo '{}'`) already used for its sibling `validate-plan-write.sh`.
2. **(IN-02)** Fix `literature`'s `keyword_overrides` schema. *Preserved functionality*: identical trigger keywords (literature, zotero, bibliography, citation) and identical target task_type (`meta`) — only the JSON shape changes to match the schema every other consumer (`cslib`, `email`) already uses correctly.
3. **(IN-03, IN-04)** Close the two `check-extension-docs.sh` FAIL categories (core's missing `provides.scripts` entries; lean's dangling `routing_hard` targets) so the project's own doc-lint returns to a clean PASS. *Preserved functionality*: IN-03 is pure manifest bookkeeping (no script behavior changes); IN-04's three options (author the skills / remove the entries / harden the router) each preserve the current, working non-hard lean routing paths and the documented Step-1-4-trusted / Step-5-gated precedence model for every other extension.
4. **(IN-05, IN-07, IN-08)** Consistency and wiring fixes for sourced-library error signaling, the unused vault-threshold script, and the unused handoff validator. *Preserved functionality*: IN-05 preserves the observable top-level failure behavior (nonzero exit, same stderr message) for any caller that doesn't specifically branch on the return code; IN-07 preserves the exact threshold value (1000), the `AskUserQuestion` confirmation flow, and the renumbering preview, only delegating the "is it exceeded" check; IN-08 preserves `skill-orchestrate`'s existing failure-handling contract (mark `failed_tasks`, skip) by mapping validation failure onto that same existing path rather than introducing a new failure mode.
5. **(IN-06)** Extract the duplicated `format_size()`/age-helpers and the colors+counters preamble into two small shared libs. *Preserved functionality*: every script's current thresholds, protected-path lists, and confirmation semantics transfer unchanged — only the identical arithmetic/formatting/preamble code is deduplicated, not the differing policy each script layers on top.
6. **(IN-09 through IN-15)** Low-severity cleanup batch: remove/archive `literature-audit.sh`; normalize the `zotero-generate-export.sh` jq style; standardize shebangs; add `email`'s missing `hooks: {}` key; widen `task-lock.sh`'s scope-mutex wait timeout; single-pass `generate-todo.sh`'s per-task lookup; simplify or align the two `state.json`-matching `settings.json` hooks. *Preserved functionality*: every item in this batch is either a pure no-op refactor (style, dead code removal, single-key schema addition) or, for IN-13/IN-14, an internal-implementation-only change that leaves every documented exit code, output format, and caller-visible contract identical.

## Risks & Mitigations

- **Risk**: Wiring `validate-meta-write.sh` (IN-01) into a live hook chain that already runs multiple `PostToolUse` handlers could add latency to every Write/Edit. *Mitigation*: the hook already short-circuits in ~1ms for non-`.claude/` paths (confirmed by reading its early-exit logic), matching the performance profile of the already-wired `validate-plan-write.sh`.
- **Risk**: Changing `literature`'s `keyword_overrides` schema (IN-02) could newly route tasks that previously fell through to the hardcoded keyword table or `general` default. *Mitigation*: this is the intended, documented behavior (task.md's own Stage 4b) — the fix restores a documented feature to working order rather than introducing new behavior; the "Otherwise -> general" fallback and the hardcoded table's own literature-adjacent entries (none currently exist) are unaffected.
- **Risk**: Widening `task-lock.sh`'s mutex timeout (IN-13) increases worst-case wait time for a caller during genuine contention. *Mitigation*: the scope-lock mutex is documented as guarding only a brief scan+decide critical section (typically sub-second), so the new upper bound (~11s) is a safety margin for pathological cases, not an expected common-case wait.
