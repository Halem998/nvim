## High Priority Issues

### 2. The precondition-gate probe (`email-census --account logos --help`) does not actually test account acceptance
**File**: `.claude/extensions/email/skills/skill-email-cleanup/SKILL.md:50-51`
**Description**: `--help` short-circuits before flag validation (per `wrapper-contracts.md:41`,
`--help` prints verb/flags), so `email-census --account logos --help` exits 0 regardless of
whether the binary validates `--account logos`. The gate's "STOP if the wrapper still rejects it"
can silently pass.
**Impact**: Reduced but real — the wrapper's own `--account` validation still hard-fails a real
call (no silent Gmail fallback), but the failure surfaces later/uglier instead of as the intended
clean actionable message. Now that task 79 has landed, the probe should confirm *liveness*, not
gate against absence.
**Recommended fix**: Use a genuinely read-only probe without `--help` (e.g. `email-census
--account logos`, read-only by safety class) and check exit code/stderr.

### 4. Pilot-ack file convention left to per-invocation agent judgment
**File**: `.claude/extensions/email/skills/skill-email-cleanup/SKILL.md:428-436,437-442`
**Description**: The skill says to use either a top-level `"account"` field OR separate per-account
ack files and "pick one convention" — but each invocation is a fresh agent with no memory of the
prior choice, and the Stage 0 gate check doesn't name the file(s) to look for. A later run could
pick the other convention and miss a legitimate prior ack.
**Impact**: Conservative failure (over-refusal, not a safety hole), but a functional inconsistency.
**Fix**: Hardcode one convention (single file, `"account"`-keyed) and have the gate always check
that path.
