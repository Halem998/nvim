## Overview

Reduce the eagerly-injected `.claude/CLAUDE.md` surface by removing content that is genuinely
duplicated elsewhere, relocating operator-only reference prose off the eager path, and installing
a per-extension byte ceiling so the next regression is detectable. All edits land in
`agent-system/extensions/**` (the source store); `.claude/**` is only ever regenerated by
`bash .claude/scripts/deploy-headless.sh` and re-measured. Every phase ends with a real deploy and
a recorded before/after byte measurement, so no phase can close on an unquantified "slimmed"
claim, and abandoning any phase leaves the source store and the deployed tree mutually consistent.

Definition of done: the four adopted levers are landed with measured deltas, one capability
consolidation is documented per removed workflow, and a byte ceiling exists in a named file that a
lint rule enforces.

## Capability Consolidations (Named Explicitly, With Before/After)

Per the binding constraint, each removed workflow is named with a before/after description. A
capability may be reached by a different route; none may disappear.

**1. `--lit` Stage 4a mechanics (Lever A)**
- *Before*: a reader wanting the resolver directives, the four interactive options, or the
  sparse-coverage re-prompt behavior finds a prose restatement in CLAUDE.md, and a fuller,
  executable version in `lit-stage4a-flow.md`. The six `--lit`-capable skills only ever read the
  latter.
- *After*: CLAUDE.md carries a short pointer paragraph naming `lit-stage4a-flow.md` as the single
  canonical contract. The skills' behavior is byte-identical (they never read CLAUDE.md for this).
  A human auditor follows one named path instead of reading a copy that can drift.

**2. Hard-mode routing ladder (Lever B)**
- *Before*: two independently-maintained copies of the identical 5-step `--hard` resolution ladder
  — CLAUDE.md's "Routing Mechanism" subsection and `hard-mode-routing.md`. The latter's Scope note
  explicitly forbids syncing them, i.e. drift is tolerated as policy.
- *After*: CLAUDE.md keeps only the cross-reference sentence its subsection already ends with.
  `hard-mode-routing.md` becomes the sole edit target, and its Scope note is updated to drop the
  now-obsolete "Do NOT edit CLAUDE.md based on this document" caveat.
- *Unchanged*: anyone needing the exact ladder still finds it via the same backticked path
  CLAUDE.md already names. Routing itself is code-driven (`manifest-routing-lib.sh`) and is not
  touched.

**3. Utility-script discovery (Lever D1)**
- *Before*: an operator asking "what does `assess-repo-health.sh` do, and who calls it?" reads the
  "Utility Scripts" subsection of CLAUDE.md — content injected into every session even though
  several entries are annotated "no automated caller by design".
- *After*: the same list, unabridged, lives in a new `docs/reference/utility-scripts-inventory.md`,
  reachable from a one-line pointer under Command Reference and from the docs index. The operator
  workflow is one `Read` longer; no entry is dropped or summarized away.

**4. Skill/agent purpose lookup (Lever D2)**
- *Before*: CLAUDE.md's Skill-to-Agent Mapping carries Skill, Agent, Model, and Purpose columns,
  plus a separate `### Agents` subtable repeating each agent with a one-line purpose.
- *After*: the table keeps the Skill -> Agent pairing (unique, not harness-provided) and drops the
  Purpose/Model columns and the `### Agents` subtable. "What is this skill/agent for?" is answered
  by the harness's own native listing, injected free every session. "Which agent does this skill
  dispatch to?" is still answered in place.

## Rollback/Contingency

Each phase is one commit scoped to `agent-system/extensions/**` plus `specs/**`. Because
`.claude/**` is a pure function of the source store, rollback is always two steps: `git revert` the
phase commit, then re-run `bash .claude/scripts/deploy-headless.sh`. The deployed tree returns to
exactly its prior state; no manual `.claude/` repair is ever needed or permitted.

Phase-specific contingencies:
- **Phase 1**: if the eager-prefix total does not reproduce 70,160 B, stop and re-derive the
  composition before proceeding. No cut phase may run against an unconfirmed baseline.
- **Phase 2**: if any removed `--lit` directive turns out to have no counterpart in
  `lit-stage4a-flow.md`, retain that sentence and reduce the claimed saving accordingly.
- **Phase 3**: if the trailing cross-reference sentence is lost, restore it before deploying — it is
  the sole mitigation for the stranded-reader risk.
- **Phase 4**: if the doc-lint fails on cross-references, revert the pointer edit and keep the
  subsection eager until the inventory doc lints clean. A failed relocation must not leave the
  content deleted from both places.
- **Phase 5**: if the measured saving falls well below the ~1,000 B floor, abandon the phase rather
  than compressing further into the Skill -> Agent pairing, which is the non-duplicated half.
- **Phase 6**: if the ceiling rule cannot be wired without destabilizing the doc-lint gate, land the
  budget config and the standard update alone (documentation-only ceiling), and record the
  unenforced state explicitly rather than claiming enforcement.
- **Abandonment at any point**: the levers are independent. Stopping after any completed phase
  leaves a smaller, consistent, fully measured tree — the cuts already landed remain valid.
