## What NOT to Try

- Do not hash raw file bytes for content-hash equality — it produces false positives on any
  source file lacking a final trailing newline, which the copy engine (by design, via
  `vim.fn.writefile`) always adds on write. Hash `vim.fn.readfile`-joined content instead.
- Do not anchor `grep` patterns to `^` when parsing headless-nvim stdout captured via
  `$(nvim --headless ... 2>&1)` in this environment — an OSC7 escape sequence can be prepended to
  the first line with no newline separator. Use unanchored `grep`/`grep -o` instead.
