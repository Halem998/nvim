## Key Decisions Made

Three hazard classes were identified across Phase 6's 5-file audit — these are the reusable
playbook for Phase 7:

1. **Bare `VAR=$(cmd)` command substitution assignments** with no explicit `||` guard, not
   already the condition of an `if`/`while`. Fix: append `|| true` when the caller's existing
   downstream logic already treats an empty/missing result as graceful degradation (the dominant
   case — `[ -n "$var" ]` checks, `// empty`/`// []` jq defaults, etc.).

2. **The `VAR=$(cmd); status=$?` anti-pattern** — capturing a command's output and exit status on
   two separate lines. This is the MOST DANGEROUS class: under `set -e`, a failing first-line
   assignment aborts the script immediately, before `status=$?` ever runs, silently destroying
   any downstream logic that branches on that status (retry loops, graceful-degradation
   reporting, documented exit-code contracts). Found and fixed 5 times across Phase 6: once in
   state-write.sh (Phase 6.1, prior dispatch), once in task-lock.sh's `cmd_acquire_retry`, twice
   in git-commit-scoped.sh (primary commit + index.lock retry), once in orchestrate-batch-admit.sh
   (`verdicts`/`jq_exit`), and twice in orchestrate-predispatch-review.sh (`ab_findings`/`jq_exit`
   and — most consequentially — `admit_output`/`admit_exit`, whose failure path drives a
   documented graceful-degradation report section). Fix: convert to
   `if VAR=$(cmd); then status=0; else status=$?; fi`.

3. **The `[ cond ] && action` bare-statement class** — e.g. `[ -n "$x" ] && echo ... >&2`,
   `[ cond ] && continue`, `[ "$FLAG" = true ] && return 0`. This is `-e`-hostile whenever the
   CONDITION is false (the common case), not just when the guarded action fails — a subtlety easy
   to miss since it looks like ordinary short-circuit idiom. Found in task-lock.sh (6 sites) and
   orchestrate-predispatch-review.sh (1 site). Fix: append `|| true`.

For heavily-reused leaf helper functions (task-lock.sh's `read_holder_field`,
`session_registry_dir`), guard the function's OWN internal hazard once at its definition rather
than at every call site — this collapsed ~15 call-site edits into 1-2 source fixes each.
