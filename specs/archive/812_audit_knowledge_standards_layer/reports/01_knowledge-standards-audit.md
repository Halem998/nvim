## Executive Summary

- **Two critical, mechanically-confirmed defects** would affect every command invocation: (1) `repo/project-overview.md` is `always: true` in `index.json` and unconditionally `@`-imported by `CLAUDE.md`, but the file does not exist on disk (KS-01); (2) `index.schema.json`'s `load_when` sub-schema still declares a `languages` property where 115/155 entries (74%) actually use `task_types`, meaning three-quarters of the index is schema-invalid under `additionalProperties: false` (KS-02).
- **`line_count` is stale for 95/155 entries (61%)**, independently reproduced by the repo's own `validate-context-index.sh`, undermining every documented token-budget calculation (KS-03).
- **The single largest, most concrete waste-of-context finding**: `meta-builder-agent` currently auto-loads 2,434 lines of explicitly self-marked `DEPRECATED (2026-01-19)` orchestration content *in addition to* the 3 files that superseded it, for a combined 4,534-line orchestration/ budget on every meta-task dispatch — a direct, quantified instance of the "context rot" failure mode current (July 2026) context-engineering guidance identifies as the top scaling risk (KS-05).
- **Systemic stale path references**: 35 occurrences across 14 files use dead singular-form paths (`.claude/agent/...`, `.claude/command/...`) that never existed under `.claude/`'s actual plural directories (`agents/`, `commands/`); three of the referenced agent files (`git-workflow-manager`, `status-sync-manager`) no longer exist under any name — they were absorbed into direct-execution skills (KS-07).
- **The exact `.opencode/` stale-reference pattern named in the task brief is confirmed** and traced to its root cause: the shared extension source `.claude/extensions/core/context/formats/return-metadata-file.md` hardcodes `.opencode/` paths regardless of sync target (KS-06).
- **6 context files exist on disk with zero index.json entry** (permanently unreachable via documented jq-discovery), including two that are directly named in `CLAUDE.md` itself (KS-10).
- Severity tally: **2 critical, 5 high, 6 medium, 2 low** (15 findings total, IDs KS-01..KS-15).

## Context & Scope

This audit covers the knowledge/standards layer only: `.claude/rules/` (10 files), `.claude/context/` (155 indexed + 6 unindexed = 161 files), and `.claude/docs/` (guides, architecture, reference/standards, templates, examples). It explicitly excludes commands/skills/agents (task 811's territory) and scripts/extensions/hooks/settings (task 813's territory) except where a finding's *governing document* lives in this layer even though its *implementation* lives elsewhere — those cases are flagged "sibling note" and left undeepened per the batch coordination instructions.

Findings were verified against `git diff`/`git show HEAD` to confirm they are pre-existing drift, not artifacts of the concurrent uncommitted batch work (804 `--fable` docs, 808/809 task-lock.md/file-footprint-overlap.md, 810 gate-script refactor) — the `index.json` working-tree diff, for example, is confirmed to be a pure key-reordering/reserialization with **zero** entry-count or path changes versus `HEAD`, so every drift finding below predates the current batch.

## Prioritized Recommendations

1. **Fix KS-01 and KS-02 first** (both critical, both affect every command invocation via `always:true` context and the vast majority of `load_when` entries respectively). Neither requires touching agent/skill/script code — both are pure `.claude/context/` and `.claude/context/index.schema.json` edits.
2. **KS-05 next** (high severity, single largest quantified token-budget win: removes 2,434 lines of duplicate/deprecated content from every `meta-builder-agent` dispatch) — pairs naturally with KS-03 (line-count refresh) since both touch the same entries.
3. **KS-04, KS-07, KS-10** (high/medium, all mechanical dead-reference or malformed-entry fixes with no design ambiguity) can be batched together as a single "reference hygiene" pass.
4. **KS-06** should be fixed at the shared extension source (`.claude/extensions/core/...`) rather than the deployed `.claude/` copy, so the fix propagates to both `.claude/` and `.opencode/` sync targets without divergence — coordinate with whichever task owns extension-source edits if that differs from this task's scope.
5. **KS-09, KS-11, KS-13** (medium) are independent, low-risk cleanups that can be done in any order.
6. **KS-08, KS-12, KS-14, KS-15** either straddle sibling task 813's territory (scripts/extensions) or are informational/process-level — flag for cross-referencing in task 814's synthesis rather than resolving unilaterally here.

Every recommendation above is stated as a metadata/documentation/cross-reference correction, not a functional or architectural change: no command, skill, or agent behavior is proposed to change, and no file is proposed for deletion (deprecated content is proposed for correct *labeling and unloading*, not removal, per KS-05's explicit "preserve" note).

## Risks & Mitigations

- **Risk**: Fixing KS-02 (schema) without also auditing all 155 entries against the corrected schema could reveal further hidden violations. **Mitigation**: schema fix should be followed by a full `ajv validate` (or equivalent) pass before considering the schema itself "done" — not performed in this audit since `ajv` was unavailable in this environment (noted, not blocking: `validate-context-index.sh`'s manual checks substituted).
- **Risk**: KS-05's `meta-builder-agent` load_when edit could remove content some workflow still depends on. **Mitigation**: the 3 deprecated files' own text explicitly states they're superseded by specific named replacements already in the same agent's load list — the replacements were verified present, not just the deprecation notices.
- **Risk**: KS-01's remediation (running `/project-overview` or restoring the generic template) could get out of sync with `.syncprotect`'s existing protection intent if the wrong path is chosen. **Mitigation**: both remediation paths are explicitly documented in `CLAUDE.md`'s own "New repository setup" note; this audit does not choose between them, deferring to whoever implements the fix.

- **Topic**: Rules-file frontmatter contract (surfaced by KS-09). **Gap**: no document anywhere in `.claude/docs/` specifies the `paths:` YAML frontmatter format that 9/10 rule files use. **Recommendation**: create `.claude/docs/reference/standards/rules-format-standard.md` (or a short section in an existing workflows doc) documenting the format, to prevent recurrence of the `neovim-lua.md`-style drift.
- **Topic**: Index-metadata freshness enforcement (surfaced by KS-15). **Gap**: no automated gate keeps `index.json` accurate after the fact; a validator exists but is not wired in anywhere. **Recommendation**: task 813 (scripts/hooks territory) should evaluate adding `validate-context-index.sh` as a pre-commit or CI hook scoped to `.claude/context/**`.
