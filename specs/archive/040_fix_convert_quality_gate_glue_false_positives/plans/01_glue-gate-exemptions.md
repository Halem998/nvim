## Overview

`sentence_boundary_glue_count` in `agent-system/extensions/literature/scripts/literature-convert.sh`
counts raw `[a-z]\.[A-Z]` transitions and, at `>= 3`, causes `run_quality_gate` to reject an
otherwise-clean conversion (output diverted to `rejected_path`, no final `.md`, `sys.exit(3)`).
Two benign corpus-endemic patterns collide with that regex: the `h.D` inside `Ph.D.` bibliography
entries, and the `{var}.{Upper}` inside binder notation (`∀x.P`, `∃y.E`, `∃x.Q`). The fix strips
those two exemption spans from the text *before* counting, leaving the threshold and the other
four gate checks untouched, and adds both-polarity hermetic regression fixtures so neither the
exemption nor the check's real purpose can silently regress.

Definition of done: the two named real papers pass the gate, genuine fused-word corruption still
exits 3 with `.rejected` written, both fixtures are generated by `generate-test-fixtures.py` and
wired into `test-literature-convert.sh` as required non-skipping assertions, the docstring records
the exemptions and their empirical motivation, and the whole suite is green.

### Research Integration

The research report established and simulation-validated the fix direction, which this plan adopts
verbatim rather than re-deriving:

- The gate runs inside a `python3 << 'PYEOF'` heredoc (`literature-convert.sh` ~lines 256-767), so
  the engine is plain Python `re` — no engine-portability constraint, and strip-then-count avoids
  Python's fixed-width-lookbehind limitation entirely.
- Exact recommended body: `re.sub(r"Ph\.D\.?", "", text)`, then
  `re.sub(r"[∀∃λ][a-z]\.[A-Z]", "", ...)`, then the original
  `re.findall(r"[a-z]\.[A-Z]", ...)` on the residue.
- Verified against real corpus text: `pym_ohearn_yang_2004` 4 -> 0, `ishtiaq_ohearn_2001` 7 -> 0,
  synthetic genuine-fusion sample still 3 (still fails).
- Fixture infrastructure survey: `generate-test-fixtures.py` has two `build_*_pdf` builders plus a
  `main()` `sys.argv[1]` dispatch; `test-literature-convert.sh` is `set -uo pipefail` with a
  `mktemp -d` `WORKDIR` + `trap ... EXIT`, `t_pass`/`t_fail` counters, and forced
  `LITERATURE_CONVERTER=pymupdf` for determinism.
- The report flagged the `λ` binder as a judgment call (no `λ` instance in the evidence). This plan
  keeps `λ` in the class: it is the same single-letter-variable binder shape, and including it
  changes neither named paper's outcome nor the synthetic fusion case.

**Planning-time addition beyond the report** (empirically probed during planning, load-bearing for
Phase 2): `page.insert_text(..., fontname="helv")` — the API both existing fixture builders use —
**cannot** carry `∀`/`∃`. It silently substitutes `·` (U+00B7); `fontname="china-ss"` drops the
character entirely. Confirmed working alternative, hermetic and with no new dependency:

```python
tw = fitz.TextWriter(page.rect)
tw.append((72, y), "Assume that ∀x.P and ∃y.E and ∃x.Q hold in the model.",
          font=fitz.Font("helv"), fontsize=11)
tw.write_text(page)
```

Round-trip verified: extracted text preserves `∀x.P`, `∃y.E`, `∃x.Q` exactly, giving 4 raw
`[a-z]\.[A-Z]` hits (3 binder + 1 `h.D`) and 0 after the fix. This removes the report's primary
fixture risk before implementation starts.

## Goals & Non-Goals

**Goals**:
- Narrow `sentence_boundary_glue_count` so `Ph.D.`/`Ph.D` and binder-adjacent single-letter-variable
  notation are exempted before counting.
- Preserve the check's real purpose: genuine zero-space sentence/word fusion still counted and still
  rejected.
- Add a negative fixture (Ph.D. + binder notation, must PASS, exit 0) and a positive fixture (fused
  -word corruption, must FAIL, exit 3 + `.rejected` + no final `.md`), both generated by
  `generate-test-fixtures.py` and wired as required non-skipping assertions.
- Update the function docstring to record both exemptions and their empirical motivation, matching
  the existing comma/semicolon precedent already documented there.

**Non-Goals**:
- Raising or otherwise changing the `>= 3` threshold in `run_quality_gate`.
- Touching the other four gate checks (column-interleaving, page-coverage, ligature-scan,
  dehyphenation-check) or `run_quality_gate`'s reason-collection/exit-3 structure.
- Reconverting, reading, or mutating anything under `~/Projects/Literature/` — the real corpus is
  out of scope for every phase, including verification.
- Editing the deployed `.claude/**` tree, or re-running deploy/sync as part of this task.
- Broadening the exemption beyond the binder-adjacent shape (no bare
  `single-letter-then-period-then-capital` exemption).

## Rollback/Contingency

- All three source files are tracked and each phase commits separately, so
  `git revert <phase-commit>` restores any single phase independently. Reverting Phase 3 alone
  restores the original gate behavior while leaving the fixtures in place (Test 3 would then fail
  loudly — the intended signal, not a silent regression).
- Contingency if the negative fixture cannot be made to clear `>= 3` raw hits while keeping the
  other four checks quiet (detected in Phase 1, before any source edit): enrich the fixture with
  additional `Ph.D. thesis,` bibliography entries, which raise the raw count one hit each with no
  effect on coverage, ligature, dehyphenation, or column-interleaving. Only if that also fails
  should the fixture be split into two PDFs (one Ph.D.-only, one binder-only), each wired as its
  own required assertion — reaching the same both-polarity coverage at the cost of one extra
  fixture kind.
- No deploy/sync step is performed by this task, so there is nothing to unwind in `.claude/**`.
