**Key Decisions Made**:
- **Critical namespace discovery**: `chunks_data.doc_id` (and chunks.json's `doc_id`) is ALWAYS
  the bare source directory name — a namespace independent of index.json's `.id`/`.parent_doc`
  fields. literature-search.sh's fidelity lookup is keyed by directory name (derived from each
  stamped entry's `.path` field). literature-briefing.sh's per-repo mode, by contrast, correctly
  uses `.id`-keyed lookup, because `specs/literature-index.json`'s `doc_id` values are curated in
  index.json's OWN `.id` namespace (confirmed against two real per-repo sub-indexes in
  ~/Projects/BimodalLogic and ~/Projects/cslib). These are two genuinely different, non-
  interchangeable namespaces for the same corpus — do not assume one script's `doc_id` lookup
  pattern transfers to the other without checking which namespace is in play.
- Bash unquoted heredocs (`<< PYEOF`) undergo command substitution on backticks anywhere in the
  body, including inside Python comments/docstrings. Do not use backtick-quoted inline code in
  any comment/docstring inside an unquoted heredoc in these scripts — use plain text instead.
- Phase 4's marker-trigger set is intentionally narrower than Phase 3's do_read banner-trigger
  set: only `unverified_summary`/`unverified_no_baseline`/absent get the briefing marker (matches
  do_search's quarantine-exclusion set exactly), while do_read's banner fires for ANY non-
  `verified_conversion` value including `no_source_pdf`/`not_yet_converted`. This is a deliberate
  plan-specified asymmetry, not an inconsistency to reconcile.
