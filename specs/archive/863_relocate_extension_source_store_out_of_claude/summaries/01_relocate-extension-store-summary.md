## Decisions

- Derived `sync.lua`'s `core_source_base` from the already-in-scope `extension_cfg` local
  (populated via `get_extension_config`) rather than a fresh `ext_config.claude(global_dir)`
  call — same canonical source, one fewer redundant computation.
- Scoped the documentation sweep to genuine SOURCE-store descriptions only. A naive
  `grep -rl '.claude/extensions' --include='*.md'` surfaced 1506 hits; the overwhelming majority
  (~1400) fall into categories confirmed out of scope: `specs/**` historical artifacts (1360),
  `.claude/**` deployed-tree copies regenerated by the next real sync (41), the
  `.claude/extensions/*/manifest.json` runtime-stub reads by `command-route-skill.sh`/
  `skill-base.sh` (do-not-touch list), and a widespread pre-existing `@.claude/extensions/{name}/
  context/...`-style citation pattern used throughout individual extension docs that was already
  incorrect before this relocation (verified via `loader.lua:273`'s `copy_context_dirs()`: context
  flattens to `.claude/context/{context_path}` with no per-extension segment at all, so this
  pattern was never accurate and the store move neither fixes nor worsens it).
- Verified the self-rebuild property via `manager.load("core"/"nvim", ...)` with both `global_dir`
  and `project_dir` pointed at a scratch copy, rather than driving `sync.load_all_globally()`
  directly — that function hard-codes `project_dir = vim.fn.getcwd()` and gates on an interactive
  `vim.fn.confirm()` dialog unsuitable for headless verification, whereas `manager.load` exercises
  the identical `manifest.lua`/`loader.lua` source-resolution code path and accepts injectable
  paths.
