# Error Recovery Strategies

This is the lazily-loaded companion to `rules/error-handling.md`. The eager core there carries
the Error Categories taxonomy, a short pointer for logging an error, the Preserve
Progress/Enable Resume/Report Clearly response shape, the Severity Levels table, the
write-gating "never discard uncommitted changes for a build fix" constraint, and the
Non-Blocking Errors list — everything an agent must know before it acts on a failure. This file
carries the reactive, per-error-type recovery detail: useful once a specific error has already
occurred, never itself a pre-action gate.

## Log the Error — Full CLI Invocation and Field Specification

Record the error via `scripts/errors-append.sh append`, which builds a schema-valid record and
writes it under `flock`:
```bash
.claude/scripts/errors-append.sh append \
  --type error_type --severity critical|high|medium|low --message "Error description" \
  --session "$session_id" --command /implement --task "$task_number" --phase 2 \
  --checkpoint GATE_OUT \
  --suggested-action "How to recover" --auto-recoverable true
```

The seven required fields are `id`, `timestamp`, `type`, `severity`, `message`, `context`, and
`fix_status` -- `id`/`timestamp`/`fix_status` are generated by the script; `context` is the
union-superset object `{session_id, command, task, phase, checkpoint, agent, file}` (no
individual sub-field required); `trajectory` and `recovery` are optional. The formal contract
lives in `context/schemas/errors-schema.json`, with the full CLI/field prose contract in
`context/formats/errors-format.md` -- the two must stay in sync.

### Session-Aware Error Aggregation

Errors with the same session_id belong to the same operation. Use session_id to:
- Link related errors in multi-step operations
- Identify recurring patterns across operations
- Enable trajectory reconstruction for debugging

## Recovery Strategies

### Timeout Recovery
```
1. Save partial progress
2. Mark current phase [PARTIAL]
3. Git commit progress
4. Next /implement resumes
```

### State Sync Recovery
```
1. Read both files
2. Use git blame for latest
3. Sync to latest version
4. Log resolution
```

### Build Error Recovery
```
1. Capture error output
2. Log to errors.json
3. Fix forward: correct the source to resolve the error. Never discard uncommitted changes
   to reach a passing build - see .claude/context/contracts/recovery.md for the full recovery
   ladder (fix forward -> strategic-sorry skeleton -> snapshot-then-rollback) and the "No
   Destructive Git on Uncommitted Work" rule in git-workflow.md.
4. Report error with context
```

Note: the "never discard uncommitted changes" prohibition above is restated as a standalone
write-gating constraint in the eager core (`rules/error-handling.md`), since it gates a
destructive operation regardless of which recovery-strategy narrative an agent has read.

### jq Parse Failure Recovery
```
1. Capture jq error output (INVALID_CHARACTER, syntax error)
2. Log to errors.json with original command
3. Retry using "| not" pattern from jq-escaping-workarounds.md
4. If retry succeeds, log recovery
```

**Note**: jq failures are often caused by Claude Code Issue #1132 variants:
- **Pipe injection**: `|` in quoted strings triggers `< /dev/null` injection
- **`!=` escaping**: The `!=` operator gets escaped as `\!=`

**Solution**: Use `select(.type == "X" | not)` instead of `select(.type != "X")`.
See `.claude/context/patterns/jq-escaping-workarounds.md` for full documentation.

### MCP Abort Error Recovery
```
1. Log the error with tool name and context
2. Retry once after 5-second delay
3. Try alternative tool if available
4. Write partial status to metadata file with partial_progress
5. Continue with available information or return partial
```

**Note**: MCP AbortError -32001 is often caused by resource contention. Retry the operation
after a brief delay.

### Delegation Interrupted Recovery
```
1. Check metadata file for status="in_progress"
2. Extract partial_progress to determine resume point
3. Keep task status unchanged (still "researching" or "implementing")
4. Log error with partial_progress context
5. Display guidance: "Run command again to resume"
```

**Note**: Delegation interrupted occurs when an agent is terminated (by timeout, MCP error, or
Claude Code abort) before writing final metadata. The early-metadata-pattern.md ensures
metadata exists for recovery.
